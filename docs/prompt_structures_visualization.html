3.1 Transcript Correction

supabase/functions/transcripts-check/index.ts
PROMPT transcripts-check: SYSTEM: "You are an enterprise-grade transcription correction agent. You MUST NOT rewrite the full transcript. You MUST NOT invent information. You MUST NOT change the meaning of any sentence." CONTEXT [stacked, all optional, injected if supplied]: ① Glossary // term mappings: "wrong → correct" ② Project Memory // projectSummary from prior meetings ③ Project Context // user free-text notes ④ Additional Context ⑤ Omit / Redaction Rules INSTRUCTION: "CRITICAL: Context-based and general corrections are ADDITIVE, not mutually exclusive." 1. Check context-based issues first // glossary, omit rules 2. Check general issues always // misspelling, vague wording, abbrev. OUTPUT (strict JSON): { suggestions: [{ segmentId, originalText, suggestedText, reasoning, confidence, // 0.0 – 1.0 issueType, // "incorrect_domain_term" | "misspelling" | "omit" | … priority // "context" | "general" → context sorted first }] } BATCHING: batchSize = 30 segments FOR each batch: call LLM → parse → repair if truncated → aggregate RETURN top 30 suggestions, sorted by (priority DESC, confidence DESC) FALLBACK CHAIN (model): 1. Azure AI Foundry GPT-5.2-Chat (Responses API, max_output_tokens: 2000) 2. Azure OpenAI Chat Completions (JSON mode, max_completion_tokens: 1200) 3. Lovable gateway google/gemini-2.5-flash JSON REPAIR PIPELINE (code-level): JSON.parse() → repairTruncatedJSON() → regex extract → word-freq fallback

3.2 Meeting Summary Generation

supabase/functions/transcripts-generate-summary/index.ts
PROMPT transcripts-generate-summary: SYSTEM: "You are an expert meeting analyst. CRITICAL: Always detect the language of the transcript and generate summaries in THE SAME LANGUAGE. Keep summaries to 150-200 words. Always respond with valid JSON only." CONTEXT: transcript content ≤ 100,000 chars IF segments > 300: sample = beginning[40%] + middle[30%] + end[30%] // preserve narrative arc INSTRUCTION: "Generate EXACTLY four sections with headers in the transcript's language: EN: Meeting Purpose / Key Decisions / Action Items / Key Insights DE: Besprechungszweck / Wichtige Entscheidungen / Aktionspunkte / Wichtige Erkenntnisse 3-4 bullets per section · 150-200 words total · 4-6 topic tags" OUTPUT (JSON, max_output_tokens: 8000): { summaryText: string, // bullet-formatted, language-matched topicTags: string[] // 4-6 keywords } JSON REPAIR PIPELINE (code-level): JSON.parse() → strip markdown fences, re-parse → regex: extract "summaryText" + "topicTags" substrings → IF content.length > 50 AND not JSON: return content as summaryText → generateFallbackSummary() // speaker extraction + word-frequency
Figure 3.2 — Prompt pseudostructure: meeting summary generation.

3.3 Project Memory Generation

supabase/functions/transcripts-generate-project-summary/index.ts
PROMPT transcripts-generate-project-summary: GUARD CONDITIONS (before LLM call): transcripts = AzureSearch.filter(docType='metadata', project=project) IF transcripts == []: return { cleared: true } IF no summaryText: return { pending: true } SYSTEM: "You are a project memory generator. Create a CONCISE project-level summary (100-150 words max) with TWO sections: • Project Status: (2-3 sentences) – overall progress, key decisions across all meetings • Update: (1-2 sentences) – ONLY the latest meeting's new contributions Use bullet points, not paragraphs." CONTEXT (server-fetched, not client-supplied): LATEST MEETING: transcripts[0].summaryText PREVIOUS: transcripts[1..n].summaryText OUTPUT: plain text // not JSON CASCADE: FOR each transcript in project: AzureSearch.merge({ id: transcriptId, projectSummary: generatedText }) // all metadata docs updated → available as zero-latency context in next chat
